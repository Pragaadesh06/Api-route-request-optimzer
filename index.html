How RouteFlow Works

Every API/service is modeled as a graph node. Connections are directed edges, and routing costs represent the effort required to move between services. The C engine performs the actual graph processing and returns the result to the interface.

Algorithm Implementations

Dijkstra

Finds the minimum-cost path between nodes when all edge costs are non-negative.

Role: Weighted shortest-path optimization
Structure: Adjacency List + Binary Min-Heap
Complexity: O((V + E) log V)

Breadth-First Search

Explores the graph level by level using a queue.

Role: Unweighted traversal
Structure: Adjacency List + Queue
Complexity: O(V + E)

Depth-First Search

Explores deeply along a path before backtracking.

Role: Graph traversal
Structure: Adjacency List + Stack/Recursion
Complexity: O(V + E)

Core Data Structures

Used for: Graph Representation

Binary Min-Heap

Used by: Dijkstra

Why: Quickly selects the next lowest-cost node during exploration.

Queue

Used by: BFS

Why: Maintains strict level-by-level processing order.

Stack / Recursion

Used by: DFS

Why: Allows deep exploration and automatic backtracking.

Explain This Algorithm

Dijkstra

  1. Start at the source.
  2. Give the source distance 0.
  3. Select the currently cheapest unprocessed node using the min-heap.
  4. Relax its outgoing edges.
  5. Update cheaper distances when found.
  6. Repeat until the destination is settled or no nodes remain.
  7. Reconstruct the path using predecessors.
